Build the first production-quality version of “Khalaf Olive Groves”.

Product concept:
Khalaf Olive Groves is an AI-assisted ancient olive grove management system — a modern interface for ancient olive trees.

It turns satellite-derived tree mapping, field-worker observations, harvest traceability, family heritage rules, and lab results into one shared operational database for managing ancient Souri olive groves.

Core story:
Some of the olive trees are ancient, potentially hundreds to over a thousand years old. The grove is not just a farm; it is a living archive of Mediterranean agricultural intelligence.

The system is based on four evidence sources:
1. Family memory and inherited grove rules.
2. Per-tree GPS/tree/canopy/health data.
3. Satellite remote sensing from Pléiades 0.5m pansharpened and 2m analytic imagery.
4. Independent laboratory analysis of olive oil quality.

These sources discipline each other over time:
family memory tells us what to look for;
satellite data detects patterns;
field workers validate what is happening on the ground;
harvest records connect trees to yield;
lab results confirm oil-quality outcomes.

Architecture:
Build one shared backend API and one shared PostgreSQL database as the single source of truth.

Build two frontend applications on top of that shared backend:

1. Manager Dashboard
Route: /manager
Audience: owner, manager, agronomist.
Purpose: analyze groves, trees, satellite alerts, heritage rules, tasks, field visits, harvest records, batches, pressing runs, oil batches, and lab results.

2. Field Worker App
Route: /field
Audience: field workers using mobile phones in the grove.
Purpose: complete monitoring tasks, inspect trees/zones, upload photos, validate satellite alerts, and during harvest season record tree-level harvest traceability.

For the MVP, implement both frontends in the same Replit app/codebase, but structure the code clearly:
- shared backend API

- manager frontend

- shared types/components where useful

Harvest Mode:
Used during harvest season.

Goal:
Tree-to-oil traceability:
tree -> harvest event -> boxes -> harvest batch -> pressing run -> oil batch -> lab result

Harvest Mode daily workflow:
1. Worker selects a tree.
2. Worker starts a tree harvest record.
3. Worker takes/uploads an initial photo of the tree before harvesting.
4. 3-4 workers harvest the tree.
5. When harvesting is done, worker photographs all boxes containing olives collected from that tree.
6. System records box count, optional estimated/full weight, workers involved, start/end time, and notes.
7. Later these tree harvest records are grouped into harvest batches.
8. Batches are connected to pressing records, oil output, and lab results.

Important harvest data rules:
- Photos are evidence, not automatic truth.
- If weight is not measured, store estimated_weight_kg and mark it as estimated.
- Do not infer exact oil yield per tree unless the batch composition and weights support it.
- If multiple trees are mixed in one batch, lab results apply to the batch, not directly to each tree unless explicitly sampled that way.
- Preserve chain of custody from tree to box to batch to press to oil to lab.
- Never overwrite harvest history.
- Warn before completing a tree harvest without box photos.
- Warn before sending a batch to press without confirming box/tree contents.

The product goal:
Khalaf Olive Groves should become the shared source of truth for ancient olive tree stewardship.

It should support three evidence loops:
1. Satellite monitoring loop:
satellite signal -> tree record -> alert -> field task -> worker validation -> updated tree history

2. Field monitoring loop:
seasonal task -> worker inspection -> photo/diagnosis -> manager review -> follow-up action

3. Harvest traceability loop:
tree -> pre-harvest photo -> boxes -> batch -> pressing run -> oil batch -> lab result

This is not a generic farm management app.
It is ancient-tree stewardship software for reverse-engineering inherited olive grove wisdom with modern data.
